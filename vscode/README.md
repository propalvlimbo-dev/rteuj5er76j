# VS Code: агент внутри редактора

Все расширения ходят в один и тот же роутер (`http://127.0.0.1:8788/v1`), а он — в SmartAPI.
Это даёт общий дневной лимит расхода и одну панель на всё: <http://127.0.0.1:8788/>.

**Перед началом запустите роутер:** `windows\START-SMARTAPI.bat` (окно не закрывать).
Ключ SmartAPI расширениям не нужен — он читается роутером из переменной `SMARTAPI_KEY`.

---

## Вариант 1. Cline — агент для VS Code

Автономный агент: сам читает файлы, сам правит, показывает diff и просит подтверждение.

1. VS Code → расширения → найдите **Cline** → Install.
2. Откройте Cline (иконка на панели слева) → **Settings**.
3. **API Provider** = `OpenAI Compatible`.
4. Заполните:
   * **Base URL**: `http://127.0.0.1:8788/v1`
   * **API Key**: `freecoder` (любая строка — роутеру всё равно)
   * **Model ID**: `auto` (варианты: `smart`, `cheap`, `free`, `local`)
   * **Context Window**: `200000`, **Max Output**: `16384` (если поля есть)
5. **Done** → пишите задачу в чат Cline.

Полезно: «Auto-approve» включайте только для чтения файлов; правки первые дни
подтверждайте глазами.

## Вариант 2. Kilo Code — много режимов (Code / Architect / Debug)

1. VS Code → расширения → **Kilo Code** → Install.
2. Settings → Provider = `OpenAI Compatible`, Base URL `http://127.0.0.1:8788/v1`,
   API Key `freecoder`, Model `auto` (для сложного — `smart`).
3. Режимы переключаются на панели: Architect — «подумать и спланировать»,
   Code — «сделать», Debug — «починить».

## Вариант 3. Continue — чат, правки и автодополнение

Конфиг готов в репозитории: `vscode\continue-config.yaml`.

1. Установите расширение **Continue**.
2. Скопируйте конфиг в `C:\Users\<вы>\.continue\config.yaml`.
3. Перезапустите VS Code — появятся модели `FreeCoder auto` / `smart` / `cheap` / `local`.

## Вариант 4. Cursor, Windsurf и прочие

Логика та же: в настройках выберите провайдер **OpenAI Compatible** и впишите
base URL `http://127.0.0.1:8788/v1`, ключ `freecoder`, модель `auto`.
Если редактор не позволяет переопределить base URL — подключайтесь к SmartAPI напрямую
(`docs/03-ПОДКЛЮЧЕНИЕ-ПРИЛОЖЕНИЙ.md`), но тогда расход пойдёт мимо панели роутера.

## Какие модели выбирать в редакторе

| Модель | Когда | Расход |
|---|---|---|
| `auto` | обычная работа: Sonnet 4.6 | ×2 — рабочий режим |
| `smart` | сложные многофайловые задачи, рефакторинг: Opus 4.8 | ×4 — только по необходимости |
| `cheap` | мелкие правки и автодополнение | минимальный |
| `free` | когда дневной лимит выбран | бесплатно (Zen, Gemini) |
| `local` | код, который нельзя отправлять даже на шлюз | бесплатно, офлайн (Ollama) |

Правило простое: **`auto` по умолчанию, `smart` — точечно, `local` — для чужого кода
и секретов.** Подробнее про коэффициенты: `docs/02-КЛЮЧ-БАЛАНС-ЛИМИТЫ.md`.

## Если расширение не видит роутер

* Проверьте, что роутер жив: <http://127.0.0.1:8788/health> должен вернуть `{"status":"ok"}`.
* Base URL обязательно с `/v1` на конце и без лишнего слэша.
* Если расширение требует «валидный ключ» — впишите `freecoder`; ключей роутер не проверяет.
* `429` в чате расширения = выбран дневной лимит (`tpd`) или занят пул шлюза.
  Смотрите панель; лимит меняется в `router\providers.smartapi.json`.
* `401`/`403` = проблема с ключом SmartAPI: роутер напишет это в своём окне, а в чате
  расширения будет ошибка провайдера. Проверьте ключ в кабинете.
* Ошибка `400` с упоминанием `tools` не страшна: роутер повторит запрос без
  неподдерживаемых полей.
