# Экономия токенов

Баланс SmartAPI списывает **зачётные токены**: `токены × коэффициент модели`. Почти весь
расход агента — это не его ответы, а **история, которая пересылается заново на каждом
шаге**. Поэтому ELYTRIX устроен так, чтобы история росла медленно, а повторяющаяся её
часть читалась из кэша.

## Из чего складывается расход

```
один шаг задачи = вход (системный промпт + инструменты + вся история) + выход (ответ модели)
задача из 5 шагов = 5 таких пересылок, причём вход растёт с каждым шагом
```

| Статья | Типичный размер | Что с ней делает ELYTRIX |
|---|---|---|
| Системный промпт | ~350 токенов | один на сессию, помечен `cache_control` |
| Схемы инструментов | ~400 токенов | 6 инструментов с короткими русскими описаниями, тоже в кэше |
| Отпечаток проекта | 1 строка | вместо обхода дерева файлов: верхний уровень и ветка git |
| История | растёт | сжимается в три ступени, хвост — в кэше |
| Результаты инструментов | до 6 000 символов каждый | обрезаются по бюджету, старые заменяются пометками |
| Ответ модели | до 8 192 токенов | промпт просит отвечать в одну-две строки |

Оценить размер без запроса к шлюзу помогает локальный счётчик: латиница считается как
4 символа на токен, кириллица — 2.5. Именно так работают `ctx 4%` в статусе и порог
автосжатия.

## Механизмы экономии

### 1. Прямое соединение, без локального роутера

Агент — один процесс: учёт токенов, дневной лимит, коэффициенты и переключение форматов
живут внутри него, а не в отдельном HTTP-сервере. Меньше один хоп на каждый запрос и
одно keep-alive соединение до шлюза: TLS-рукопожатие не повторяется на каждом шаге
(экономия 100…300 мс на шаг — это про скорость, но она же снижает соблазн прерывать
задачу и начинать заново).

### 2. Промпт-кэш

Помечаются три точки: последняя схема инструмента, системный промпт и последний блок
сообщения перед свежими. Кэш Anthropic работает по префиксу, поэтому на следующем шаге
вся неизменная часть контекста тарифицируется как **чтение кэша** — заметно дешевле
обычного входа и быстрее по времени до первого символа.

Если шлюз ответил `400` на пометки `cache_control`, ELYTRIX отключает кэш до конца
сессии и повторяет запрос уже без него — задача не падает. Состояние видно в `/doctor`
(строка «кэш промпта») и в `/status.json` роутера. Выключить вручную: `--no-cache`
или `"economy": {"cache": false}`.

### 3. Сжатие истории в три ступени

Сжатие локальное: **ни одного платного запроса к модели** (в отличие от «попроси модель
пересказать диалог»).

1. **Результаты инструментов** старше последних `keep_recent` (по умолчанию 2) шагов
   заменяются одной строкой: `[сжато: read api.py · 4820 симв. · первая строка…]`.
2. **Содержимое файлов** в старых вызовах `write`/`edit` заменяется пометкой о размере:
   файл уже на диске, модели он больше не нужен в истории.
3. **Середина истории** сворачивается в «журнал» — список того, что было сделано,
   собранный из метаданных шагов. Начало (задача) и хвост (последние сообщения)
   сохраняются целиком.

После сжатия история приводится к требованиям шлюза: у каждого `tool_use` остаётся пара
`tool_result`, роли чередуются — иначе шлюз вернул бы `400` и шаг пропал впустую.

Автосжатие срабатывает, когда оценка контекста превышает `economy.compact_at` от окна
модели (по умолчанию 0.55, то есть 110 000 токенов для окна в 200 000). Вручную —
`/compact`. В ленте появляется строка `• история сжата: −12.4K токенов`.

### 4. Память сессии

Вместо всей переписки о прошлых задачах агент хранит две строки на задачу
(до 6 задач): `· починил get_user в api.py → добавил проверку на None, тест зелёный`.
Они попадают в системный промпт, поэтому продолжения вроде «а теперь то же во втором
файле» понимаются без пересылки истории. `/clear` очищает и историю, и память;
`/session` показывает, что запомнено.

### 5. Бюджет вывода инструментов

В историю не попадают мегабайты. Лимиты из `config/elytrix.json` → `economy`:

| Параметр | По умолчанию | Что ограничивает |
|---|---|---|
| `tool_result_chars` | 6000 | любой результат инструмента |
| `bash_output_chars` | 4000 | вывод команды |
| `read_chars` | 12000 | содержимое файла при чтении |
| `grep_hits` | 40 | число совпадений поиска |
| `keep_recent` | 2 | сколько последних шагов не сжимать |
| `compact_at` | 0.55 | доля контекста для автосжатия |

Обрезанный результат сопровождается подсказкой, как получить остальное
(`read` c `offset`/`limit`, `grep` с более узким `glob`), поэтому модель не пытается
прочитать то же самое целиком.

### 6. Параллельные инструменты

Независимые действия модель вызывает несколькими инструментами в одном ответе (об этом
прямо написано в системном промпте), а агент выполняет их сразу — один круг вместо трёх.
Каждый сэкономленный круг — это одна пересылка истории меньше.

### 7. Дневной лимит

Проверяется **до** отправки запроса: если расход за сутки достиг лимита, запрос не уходит
вовсе. По умолчанию 400 000 зачётных токенов — при такой норме баланса 8 000 000 хватает
примерно на 20 дней работы. Изменить: `/limit 600000`, снять: `/limit 0`. Расход
переживает перезапуск (хранится в профиле) и сбрасывается по границе суток UTC.

### 8. Failover без лишних попыток

Основной формат — Anthropic (`/v1/messages`), запасной — OpenAI (`/v1/chat/completions`).
Повтор делается только когда он осмыслен: `5xx` и обрыв потока — да, `401` и `404` — нет
(сразу понятная ошибка пользователю), `429` — ожидание `Retry-After` и одна попытка.
Неудачные попытки не дублируют расход: токены списываются только за состоявшиеся ответы.

### 9. Отмена без ожидания

**Esc** обрывает текущий запрос (сокет закрывается), а не ждёт его окончания. Ответ,
который вам уже не нужен, не успевает доесть выходные токены.

## Как платить меньше: практика

1. **Одна задача — одна тема.** Закончили — `/clear`. Следующая задача уйдёт без истории
   предыдущей, а это главная статья расхода.
2. **Называйте файлы в задаче.** «в `api.py` функция `get_user` падает на `None`» —
   агент начнёт с чтения нужного места, а не с обхода проекта.
3. **Дешёвая модель для мелочей.** `/model cheap` (×1.7) для вопросов и мелких правок;
   `smart` (×4) и `max` (×5) — только когда задача действительно сложная.
4. **Просите точечные правки.** «замени X на Y в файле Z» — один шаг `edit`,
   а не перепись файла через `write`.
5. **Не перечитывайте большое.** Читайте диапазоном: «прочитай `api.py` строки 120—180».
6. **`/compact` в длинной задаче.** Если лента выросла, а задача не закончена — сожмите
   историю руками, не дожидаясь порога.
7. **Ограничьте шаги.** `/steps 8` — потолок, после которого агент обязан отчитаться.
8. **Следите за статусом.** `ctx 62%` означает, что следующий шаг потащит всю эту
   историю: либо `/compact`, либо `/clear`.
9. **Не держите режим `verbose` включённым без нужды** — на расход он не влияет
   (это только отрисовка), но отвлекает от главного: строки `вх/вых` и `день X/Y`.

## Что показывает интерфейс

| Индикатор | Смысл |
|---|---|
| `ctx 4%` | доля контекста модели, занятая историей (локальная оценка) |
| `вх 8.2K` | входных токенов за сессию |
| `вых 640` | выходных токенов за сессию |
| `кэш 3.1K` | прочитано из кэша (дешевле обычного входа) |
| `×2` | коэффициент текущей модели |
| `день 17K/400K █░░░` | расход за сутки из дневного лимита |
| `списано 17 680 зачётных` | итог задачи: токены × коэффициент |
| `/tokens` | разбивка по моделям, последние запросы, состояние кэша |
