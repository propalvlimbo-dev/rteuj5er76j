# Устройство кода

ELYTRIX — 7 700 строк Python на стандартной библиотеке: 13 модулей в `app/elytrix/`,
точка входа `app/run.py` и 326 тестов в `dev/tests/`. Никаких зависимостей, поэтому
всё, что вы здесь видите, работает сразу после клонирования.

## Карта модулей

```

app/elytrix/
  __init__.py         12   версия пакета
  __main__.py         18   python -m elytrix
  screen.py          466   цвет и геометрия текста
  keys.py            352   ввод с клавиатуры
  theme.py           237   темы и символы рамок
  widgets.py         465   markdown, диффы, таблицы, подсветка
  config.py          464   настройки, каталог моделей, состояние расхода, ключ
  gateway.py         854   клиент SmartAPI
  tools.py           734   песочница и шесть инструментов
  agent.py           701   цикл задачи
  render.py          284   блоки ленты
  dialogs.py         356   диалоги поверх ленты
  tui.py            1787   полноэкранная консоль
  router.py          642   HTTP-шлюз для редакторов
```

Зависимости идут строго вниз: `screen` не знает ни о чём, `widgets` — о `screen` и
`theme`, `render` — о `widgets`, `tui` — обо всём. `gateway` и `tools` не знают про
интерфейс, `agent` связывает их и отдаёт события наружу через колбэк `emit`. Благодаря
этому агент тестируется без консоли, а консоль — без сети.

## Что внутри каждого модуля

### screen.py — цвет и геометрия

Терминал не знает ни про Unicode-ширину символов, ни про ваши стили, поэтому здесь:

- `is_tty`, `detect_color_mode` (truecolor / 256 / 16 / none, учитывает `NO_COLOR`,
  `COLORTERM`, `TERM`), `enable_vt` (в Windows включает
  `ENABLE_VIRTUAL_TERMINAL_PROCESSING` через `ctypes`), `force_utf8`, `supports_unicode`;
- `Palette` — превращает RGB в ESC-код нужной глубины (с округлением до палитры 256 и 16);
- `Style` — начертание и цвета, сравнимый и хешируемый (это важно для кэша строк);
- `char_width` / `text_width` / `visible_width` — ширина с учётом CJK (2 клетки),
  комбайнирующих символов (0) и ANSI-кодов (0);
- `truncate`, `wrap_line`, `wrap_text` — перенос по словам с сохранением стилей и
  разрывом длинных слов, `pad` — добивка строки до ширины;
- `terminal_size` — размер окна (в Windows через `shutil`, иначе `ioctl`, иначе
  `COLUMNS`/`LINES`).

Тип `Line = List[Tuple[str, Style]]` — «строка как список окрашенных кусков» — проходит
через весь интерфейс: его возвращают виджеты, рендеры блоков и диалоги, а `tui` просто
складывает их в кадр.

### keys.py — ввод

- `KeyEvent(name, text)` — одно нажатие: `char`, `enter`, `esc`, `up`, `ctrl+w`,
  `alt+enter`, `paste`, `resize`…
- `KeyParser` — инкрементальный разбор байтов: ESC-последовательности CSI и SS3,
  модификаторы (`\x1b[1;5C` → `ctrl+right`), одиночный Esc по таймауту 50 мс,
  многобайтовый UTF-8, приходящий кусками, и **bracketed paste** (`\x1b[200~…\x1b[201~`)
  — вставка из буфера становится одним событием `paste`, поэтому многострочный текст не
  отправляется сам собой.
- `KeyReader` — чтение из консоли: `msvcrt` в Windows, `termios` + `tty` в POSIX
  (raw-режим включается на время работы и восстанавливается при выходе), неблокирующее
  чтение с таймаутом, чтобы главный цикл успевал рисовать кадры.

### theme.py — темы

`Charset` — два набора символов: Unicode (`╭ ─ ✓ ⏵ ●`) и ASCII (`+ - v > *`) для
консолей без UTF-8. `Theme` — роли цветов (`fg`, `dim`, `accent`, `accent2`, `ok`,
`warn`, `err`, `border`, `border_active`, `faint`…) и метод `style(role, bold=…, …)`,
возвращающий готовый `Style`. Четыре темы: `dark`, `night`, `light`, `mono`. Спиннеры:
брайлевский для Unicode, `|/-\` для ASCII.

### widgets.py — рисование содержимого

`render_markdown` (заголовки, списки с вложенностью, цитаты, таблицы с выравниванием,
блоки кода с подсветкой, разделители), `inline` (**жирный**, `код`, [ссылки]() — без
самой ссылки), `render_diff` (цветной унифицированный дифф с обрезкой), `highlight`
(подсветка Python/JS/JSON/общая — своя, без внешних библиотек), `bar` (шкала), `box`
(рамка вокруг строк), `sep`, `kv_line`, и форматировщики чисел: `human_number`
(1.5K, 2.5M), `plural` (шаг/шага/шагов), `seconds_text` (2м05с).

### config.py — настройки, модели, расход, ключ

- пути: `project_root`, `home_dir` (`~/.elytrix` или `%USERPROFILE%\.elytrix`,
  переопределяется `ELYTRIX_HOME`), `state_path`, `credentials_path`, `sessions_dir`,
  `config_path`;
- `Config` — глубокая смесь `DEFAULTS` с `config/elytrix.json`, доступ по точечному пути
  (`cfg.get("limits.daily_tokens")`), `save` через временный файл и `os.replace`, плюс
  `workspace_config` — локальные настройки проекта из `<папка>/.elytrix/config.json`;
- `Catalog` — маршруты (`auto/cheap/smart/max`), коэффициенты, размер контекста,
  семейства моделей, `add_models` для моделей, которых нет в конфиге, `price_word`
  («дёшево» … «не тратить зря»);
- `State` — расход за сутки в **зачётных токенах**, счётчики по моделям, история
  последних запросов, произвольные ключи профиля (последняя папка, тема, модель);
  сброс по границе суток UTC, запись после каждого изменения;
- ключ: `read_key` (окружение `SMARTAPI_KEY` → файл профиля), `save_key` (файл с правами
  `600` в POSIX + переменная окружения процесса), `mask_key` для показа в интерфейсе.

### gateway.py — клиент SmartAPI

- `Connection` — один keep-alive канал на хост: TLS-рукопожатие не повторяется на каждом
  шаге, при обрыве соединение пересоздаётся и запрос повторяется один раз;
- `SmartAPI.chat` — основной вызов: собирает payload в формате Anthropic, при неудаче
  уходит в формат OpenAI (`to_openai`), поддерживает стриминг с колбэками `on_text` и
  `on_tool`, отмену через `threading.Event` и температуру/лимит выхода;
- `apply_cache` — три пометки `cache_control` (инструменты, system, префикс диалога);
  при ответе `400` кэш отключается до конца сессии, а запрос повторяется без пометок;
- `_read_stream` — разбор SSE обоих форматов; если поток оборвался до `message_stop` /
  `[DONE]` и ответ пуст, это ошибка с флагом `retryable`, а не «пустой ответ»;
- учёт: `estimate_tokens` (латиница ~4 символа на токен, кириллица ~2.5), умножение на
  коэффициент модели, проверка дневного лимита **до** запроса, `DailyLimitError`;
- реакции на ошибки: `401` → `AuthError` (без повторов), `404` на `/v1/messages` →
  переход на OpenAI-формат, `429` → охлаждение на `Retry-After`, `5xx` → повтор;
- `probe` (контрольный запрос на 8 токенов) и `fetch_models` (каталог шлюза) — для
  `/doctor` и `/models reload`.

### tools.py — песочница и инструменты

`Workspace` — все файловые операции: `resolve` (путь не может выйти за рабочую папку при
записи; `../` нормализуется), `walk` (без `node_modules`, `.git`, сборок и кэшей),
`snapshot` / `undo` / `session_diff` (резервные копии в
`<папка>/.elytrix/backups/<сессия>/`, для новых файлов — метка `.new`, чтобы `/undo` их
удалил), `fingerprint` (одна строка о проекте для системного промпта), `ls`, `read`
(`offset` с 1, как в редакторах), `grep` (регистр, `glob`, предел совпадений, невалидный
regex трактуется как литерал), `write`, `edit` (точная замена, затем «расслабленная» —
с нормализацией пробелов; `all` для всех вхождений), `bash` (рабочая папка, таймаут, код
выхода, stderr).

`DENY_COMMANDS` — список шаблонов, которые не выполняются никогда: `rm -rf /`,
`sudo rm`, `mkfs`, `format C:`, `shutdown`, `git push --force`, `curl … | sh`,
`iwr … | iex`, `chmod -R 777 /` и подобные. `SECRET_PATTERNS` — файлы, которые агент не
читает и не правит: `.env`, `*.key`, `*.pem`, `id_rsa`, `credentials`, `.netrc`.

`Toolbox` — единая точка входа `run(name, args)`: обрезка результата по бюджету,
счётчики вызовов, человекочитаемое `summary` для ленты. `TOOL_SCHEMAS` — компактные
JSON-схемы шести инструментов с русскими описаниями (~400 токенов на весь набор).

### agent.py — цикл задачи

`Agent.run_task(text)` → `Report`. Внутри:

1. история пополняется задачей, при необходимости включается текстовый протокол;
2. `_auto_compact` — если оценка контекста выше порога, история сжимается;
3. `_step` — один запрос к шлюзу: `sanitize_history` (пары `tool_use`/`tool_result`,
   чередование ролей), `SmartAPI.chat` со стримингом текста в интерфейс;
4. если в ответе есть инструменты — `_execute_tools`: чтения и поиск идут параллельно
   (`ThreadPoolExecutor`, до 4 потоков), правки — последовательно и только после
   подтверждения; результаты возвращаются модели блоками `tool_result`;
5. если инструментов нет — это ответ пользователю: задача заканчивается, в память
   сессии пишутся две строки (задача → итог, до 6 задач);
6. ограничения: `max_steps` шагов, отмена через `cancel`, ошибки шлюза и дневного лимита
   превращаются в понятный `Report.error`.

`compact(aggressive)` — три ступени сжатия (пометки результатов, пометки содержимого
файлов, журнал вместо середины истории) и обязательная санитизация истории после сжатия.
`text_protocol` — запасной режим, если шлюз не поддержал инструменты: модель отвечает
одним JSON-объектом `{"thought":…,"tool":…,"args":…}` или `{"done":true,"answer":…}`,
а агент разбирает его регулярным выражением и выполняет как обычный вызов.

События наружу (`emit`): `status`, `step`, `text`, `tool`, `result`, `compact`,
`task_done`, `error`, `confirm`. Подтверждения — через колбэк `confirm(ConfirmRequest)`,
возвращающий `yes` / `no` / `always` / `stop`.

### render.py — блоки ленты

`Block` — единица ленты: задача пользователя, ответ модели, инструмент, служебное
сообщение, ошибка. Блок кэширует отрисованные строки и перерисовывается только по
`touch()` (или при `append_text` — так работает стриминг). `render_tool` рисует одну
строку на инструмент (`⏵` выполняется, `✓` готов, `✗` ошибка, цель, итог, время), а в
подробном режиме — ещё и дифф или содержимое результата. `header`, `activity`,
`status_bar`, `tip_line` — шапка, строка активности, статус и совет.

### dialogs.py — диалоги

Общий каркас `Dialog` рисует ровную рамку по центру ленты, умеет прокрутку и подсказку
внизу, а `key()` возвращает `None` (остаёмся) или результат (закрываемся). Наследники:
`MessageDialog` (текст/markdown), `ListDialog` (выбор стрелками, цифрами или набором
текста), `PromptDialog` (однострочный ввод с кареткой, секретным режимом и проверкой),
`ConfirmDialog` (подтверждение правки с диффом и клавишами y/a/n/s).

### tui.py — консоль

- `InputBuffer` — многострочное поле с кареткой, историей и черновиком;
- `Completion` — подсказки команд и путей;
- `App` — главный цикл: чтение клавиш с таймаутом 50 мс, разбор очереди событий от
  воркера, перерисовка только когда кадр «грязный» или агент занят (20—30 кадров/с),
  сборка кадра (шапка → лента → активность → совет → ввод → статус → диалог поверх),
  позиционирование каретки, возврат экрана при выходе;
- задача выполняется в отдельном потоке (`_worker`), поэтому интерфейс не замирает, а
  отмена и подтверждение работают во время запроса: `confirm_async` кладёт запрос в
  очередь, открывает диалог и ждёт `threading.Event` — ответ приходит из главного потока;
- `PlainUI` — тот же агент без полноэкранной отрисовки: поток текста, строка на
  инструмент, итог с расходом.

### router.py — шлюз для редакторов

Переводы форматов (`openai_to_internal`, `anthropic_to_internal`, `turn_to_openai`,
`turn_to_anthropic`), обработчик `BaseHTTPRequestHandler` с маршрутами
`/v1/chat/completions`, `/v1/messages`, `/v1/models`, `/status.json`, `/health`,
SSE-стриминг обоих форматов и `GatewayPool` — до четырёх клиентов SmartAPI, чтобы
параллельные запросы редактора не ломали друг другу keep-alive соединения.

### cli.py — режимы

`main()` решает, что запустить: `--router` → только шлюз, `--models` → каталог,
`--doctor` → диагностика, задача текстом (или не-tty, или `--plain`) → `PlainUI`,
иначе → полноэкранная `App`. Здесь же сборка агента из конфига, каталога, состояния,
шлюза, рабочей папки и набора инструментов.

## Поток данных одной задачи

```
клавиатура ──► KeyReader ──► KeyParser ──► App.on_key ──► App.submit
                                                              │
                                              (команда «/…»)  │  (задача)
                                                     ▼        ▼
                                            App.command   App.start_task
                                                              │  поток
                                                              ▼
                                                        Agent.run_task
                                                              │
                       ┌──────────────────────────────────────┤
                       ▼                                      ▼
              SmartAPI.chat (SSE)                    Toolbox.run (инструменты)
                       │  on_text                             │  ToolResult
                       ▼                                      ▼
              emit("text", …)                        emit("result", …)
                       │                                      │
                       └────────► App.queue ◄─────────────────┘
                                     │  drain() в главном цикле
                                     ▼
                              блоки ленты ──► render ──► draw ──► терминал
```

## Как расширять

### Добавить инструмент

1. В `tools.py` опишите метод в `Workspace` (файловые операции — через `resolve`,
   чтобы остаться в песочнице) и обёртку в `Toolbox` (`_my_tool`), возвращающую
   `ToolResult` с `summary` для ленты.
2. Добавьте `ToolSpec` в список инструментов и схему в `TOOL_SCHEMAS`: короткое русское
   описание экономит токены на каждом шаге.
3. Зарегистрируйте имя в `Toolbox.run` и, если инструмент что-то меняет, пометьте его
   `mutating=True` — тогда на него будут спрашивать подтверждение и делать резервную
   копию.
4. Допишите текстовый протокол в `agent.py` (`TEXT_PROTOCOL`), чтобы инструмент работал
   и на шлюзах без поддержки tools.
5. Тест в `dev/tests/test_tools.py` — по образцу соседних.

### Добавить команду консоли

1. Метод `cmd_my(self, arg)` в `App` (tui.py): `self.add(KIND_INFO, …)` для строки в
   ленте или `self.open_dialog(…)` для диалога.
2. Строка в `COMMANDS` — она же попадёт в `/help` и в подсказки ввода.
3. Регистрация в словаре `handlers` внутри `App.command` (можно дать короткий алиас).
4. Тест в `dev/tests/test_tui.py::TestCommands`.

### Добавить тему

1. В `theme.py` — словарь ролей → RGB и имя в `THEME_NAMES`.
2. Всё остальное (диалоги, рамки, подсветка) подхватит тему само: цвет берётся только
   через `theme.style(role)`.

### Стиль кода

- только стандартная библиотека — никаких `pip install`;
- строки до 100 символов, русский язык в интерфейсе и в комментариях (комментарий
  объясняет «зачем», а не «что»);
- типы — через `typing` и `from __future__ import annotations` (работает на Python 3.8);
- каждая новая возможность приходит с тестом в `dev/tests/`;
- `python dev/tests/run_all.py` должен оставаться зелёным.

`mockapi.py` поднимает настоящий локальный HTTP-сервер, который отвечает в обоих
форматах шлюза, умеет стримить по кускам, ронять ответы (`fail_with`, `reject_cache`,
`drop_tools`, `unknown_model`, `cut_stream`, `stall`) и записывать полученные запросы.
Класс `Stack` собирает из него полный агент: конфиг, каталог, состояние, шлюз, рабочую
папку, инструменты и `Agent` со сборщиком событий — поэтому тесты агента и консоли не
трогают сеть и проходят за секунды.
