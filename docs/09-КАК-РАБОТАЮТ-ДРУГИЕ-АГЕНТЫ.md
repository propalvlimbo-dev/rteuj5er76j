# Как устроены другие CLI-агенты (обзор GitHub) и что из этого есть у нас

Короткий обзор: кто сегодня делает терминальных ИИ-агентов, чем они берут и, главное,
как они экономят токены — потому что это тот же счёт, что и у нас.

## Кто есть на рынке

| Проект | Что это | Чем берёт |
|---|---|---|
| **Aider** (`Aider-AI/aider`) | терминальный парный программист, Python | git-автокоммиты на каждую правку, **repo map** — карта символов всего проекта, которая едет в модель вместо файлов |
| **OpenCode** (`sst/opencode`) | TUI-агент, TypeScript/Go | красивое терминальное окно, LSP, несколько параллельных сессий, много провайдеров |
| **OpenHands** (`All-Hands-AI/OpenHands`) | автономный агент | сам решает задачи целиком (правки, команды, браузер), Docker-песочница |
| **Codex CLI** (`openai/codex`) | агент OpenAI | жёсткая песочница выполнения, режимы подтверждений |
| **Gemini CLI** (`google-gemini/gemini-cli`) | агент Google | очень большое окно контекста (1 млн токенов) и бесплатная квота |
| **Cline / Kilo Code** | расширения VS Code | правки видно в редакторе, широкая поддержка моделей |
| **Crush** (`charmbracelet/crush`), **Goose** (`block/goose`) | терминальные/локальные агенты | аккуратный интерфейс, работа с разными провайдерами |
| **mini-swe-agent** (`SWE-bench`) | исследовательский агент | эталон простоты: весь агент — один файл |

Звёзды, размеры и лицензии меняются каждый месяц — важнее то, какие приёмы они используют.

## Приёмы, которые реально экономят деньги

1. **Не пересылать файлы целиком.** Aider строит *repo map*: разбирает проект и отправляет
   не код, а структурную карту (имена файлов, классов, функций, связи), с жёстким бюджетом
   около 1 000 токенов. Файл уходит в модель только если он нужен для правки.
   У нас вместо карты символов — дерево проекта до 120 строк и правило «читай файл по частям».
2. **Правка вместо перезаписи.** Все современные агенты предлагают модели выдать diff или
   блок «найди такой кусок — замени на такой». Модель генерирует только изменённое, а
   сгенерированные токены — самая дорогая часть. У нас это `replace_in_file`.
3. **Понятная цена работы.** У Aider есть команда `/tokens`: показывает, из чего складывается
   следующий запрос и советует, что выкинуть (`/drop`, `/clear`). У нас — `/tokens` и `/clear`.
4. **Кэш повторяющегося начала.** В запросе агента начало всегда одно и то же: инструкции,
   структура проекта, предыдущие шаги. Anthropic и Bedrock умеют кэшировать такой префикс и
   берут за него около 10 % цены входных токенов. По замерам это самая крупная экономия
   у тех, кто работает через официальный API.
5. **Две модели: архитектор и редактор.** Aider в *architect mode* планирует сильной моделью,
   а правки пишет дешёвой. По их данным это на 30–50 % дешевле, чем делать всё дорогой моделью.
6. **Ограничение зоны работы.** `.aiderignore`, флаг `--subtree-only` — агент видит только
   часть репозитория и не тащит лишнее.
7. **Лимит расхода сверху.** У всех «бизнес-версий» есть бюджет на день/месяц. У нас это
   `tpd` в `config/providers.json` — жёсткий потолок зачётных токенов в сутки.
8. **Откат вместо страховки.** Вместо «перечитать всё ещё раз» агенты полагаются на git:
   каждая правка — коммит, любую можно отменить. У нас — резервные копии и `/undo`.

## Что из этого уже есть в FreeCoder

* одно компактное окно, одна строка на шаг (вместо дампов JSON);
* сжатие истории: содержимое записанных файлов не пересылается заново;
* `replace_in_file` для точечных правок; чтение файла порциями до 8 000 символов;
* `/tokens` — разбор следующего запроса; `/clear` — новая задача без старой истории;
* `/steps 15` — предел шагов на задачу (вместо бесконечной сессии);
* дневной лимит `tpd` и предупреждение, когда он выбран;
* дешёвая модель по умолчанию и витрина моделей с коэффициентами (`/model`);
* `/diff` и `/undo` — откат всегда под рукой.

## Что осознанно не берём

* **tree-sitter и полноценная карта символов** — это внешние библиотеки и разбор всех языков;
  наш проект принципиально без зависимостей (только стандартная библиотека Python).
* **Docker-песочницу** — на домашнем Windows 16 ГБ это лишний вес; у нас ограничение
  «агент работает только внутри указанной папки».
* **LSP и индекс кода** — полезно в редакторах; в терминале проще прочитать нужный файл.
* **MCP-серверы** — удобны для больших команд, но каждая интеграция снова добавляет токены.
* **Кэш префикса** — упёрлись в шлюз: SmartAPI не подтверждает поддержку `cache_control`.
  Если появится — это следующий большой шаг экономии, код к нему готов (промпт стабилен,
  структура проекта едет в начале запроса).
