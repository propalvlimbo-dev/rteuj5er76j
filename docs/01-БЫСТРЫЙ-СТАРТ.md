# Быстрый старт

От установки до первой починенной ошибки — пять минут.

## 1. Python

Нужен Python 3.8 или новее. Проверка:

```
python --version
```

Если команды нет — поставьте Python с <https://www.python.org/downloads/> и **обязательно**
отметьте галочку **Add Python to PATH** на первом экране установщика. В Linux и macOS
Python обычно уже есть (команда может называться `python3`).

Сторонние пакеты не нужны: ELYTRIX работает только на стандартной библиотеке, никакого
`pip install`, виртуального окружения или Node.js.

## 2. Ключ SmartAPI

Ключ создаётся в кабинете <https://smartapi.shop/api-keys> и выглядит как `sk-smart-…`.
Он даёт доступ к вашему балансу зачётных токенов — ELYTRIX тратит ровно то, что списывает
шлюз, и показывает расход после каждого шага.

## 3. Первый запуск

**Windows** — двойной клик по файлу в папке проекта:

```
ELYTRIX.bat
```

Файл сам переключает консоль в UTF-8 (`chcp 65001`), находит интерпретатор
(`python` → `py` → `python3`) и открывает полноэкранный интерфейс.

**Linux / macOS / любой терминал:**

```
python3 app/run.py
```

При первом запуске агент спросит две вещи:

1. **Ключ.** Вставьте его и нажмите Enter. Символы не отображаются — так и задумано.
   Ключ сохранится в `~/.elytrix/credentials.json` с правами `600` (в Windows — в файл
   профиля) и в переменную окружения `SMARTAPI_KEY`. В файлах проекта ключ не появляется.
2. **Папку с вашим кодом.** Двойной клик открывает консоль в папке самой программы, а код
   обычно лежит в другом месте — укажите путь (можно вставить из проводника, кавычки не нужны).
   Папка запоминается: в следующий раз достаточно Enter.

Если консоль Windows оказалась древней и не понимает VT-последовательности, агент сам
переключится в обычный режим вывода — работать будет, просто без полноэкранной рамки.

## 4. Первая задача

Пишите задачу словами в поле ввода и жмите Enter:

```
> в api.py падает get_user на пустом ответе — найди причину и почини
```

Что происходит дальше:

```
  ✓ grep      get_user · 4 совпадения в 2 файлах · 0.1с     ← осмотрелся
  ✓ read      api.py · строки 120—180 · 0.0с                ← прочитал нужное
  ? edit      api.py                                        ← спрашивает разрешение
      -    return user["id"]
      +    if not user:
      +        return None
      +    return user["id"]
    y — применить · a — всегда · n — пропустить · s — остановить задачу
```

В режиме `ask` (по умолчанию) на каждую правку показывается дифф и спрашивается
разрешение. Клавиши: **y** — применить, **a** — применять дальше без вопросов,
**n** — пропустить эту правку, **s** — остановить задачу. Русские **д** и **н** тоже
работают.

Ответ модели печатается по мере генерации. В конце — строка итога:

```
  ● готово за 12.4с · 3 шага · вх 8.2K · вых 640 · списано 17 680 зачётных
```

**вх** — сколько токенов модель прочитала (история пересылается каждый шаг — это главная
статья расхода), **вых** — сколько написала, **списано** — зачётные токены, то есть
токены × коэффициент модели. Именно их списывает баланс SmartAPI.

## 5. Что сделать сразу после

| Действие | Зачем |
|---|---|
| `/confirm auto` | править без вопросов на каждую правку (откат — `/undo`) |
| `/model cheap` | для мелких правок и вопросов: ×1.7 вместо ×2 |
| `/tokens` | посмотреть, куда ушёл расход за сутки |
| `/help` | полный список команд и клавиш |
| `/clear` | начать новую тему — следующая задача уйдёт без старой истории |

## 6. Запуск без интерфейса

Одна задача и выход — удобно в скриптах и CI:

```
python app/run.py "прогони тесты и почини упавшие"
python app/run.py "объясни, что делает pipeline.py" --plain -m cheap
python app/run.py -w D:\code\my-project "обнови зависимости"
```

Если вывод не в терминал (перенаправление в файл, CI), агент сам переходит в обычный
режим: поток текста, по строке на инструмент, итог с расходом.

## 7. Диагностика

Что-то не так — сначала диагностика:

```
python app/run.py --doctor
```

Она печатает: версию и Python, состояние терминала (цвет, VT, tty), пути к конфигу и
профилю, замаскированный ключ и его источник, адреса шлюза, рабочую папку, модель с
коэффициентом и размером контекста, дневной лимит, расход за сегодня, список моделей
шлюза (и каких моделей из конфига у шлюза нет), результат контрольного запроса и
поддерживается ли промпт-кэш. В конце — где лежат журнал сессий и резервные копии.

## Частые проблемы

**«Python не найден» в окне ELYTRIX.bat.**
Python не в PATH. Переустановите с галочкой **Add Python to PATH** или запускайте через
`py app\run.py`. Окно при ошибке не закрывается — текст виден.

**«нет ключа SmartAPI».**
Ключ не задан. Запустите `ELYTRIX.bat` — он спросит и сохранит. Либо задайте переменную
окружения `SMARTAPI_KEY`. Проверить: `python app/run.py --doctor` (строка «ключ»).

**HTTP 401 / «invalid api key».**
Ключ неверный или отозван. Смените: `/key` в консоли или `--key sk-smart-…`.

**HTTP 429 / «too many requests».**
Шлюз просит притормозить. ELYTRIX ждёт указанное в `Retry-After` время (по умолчанию
60 с) и повторяет сам; в статусе видно охлаждение. Если 429 приходит постоянно — снизьте
дневной лимит (`/limit 200000`) или возьмите модель дешевле.

**Дневной лимит исчерпан.**
Запросы блокируются **до** отправки, чтобы баланс не сгорел за вечер. Снять:
`/limit 0`. Поднять: `/limit 800000`. Лимит живёт в профиле и переживает перезапуск.

**Вместо рамок — вопросы и кракозябры.**
Консоль не в UTF-8. В Windows запустите `ELYTRIX.bat` (он ставит `chcp 65001`), а не
голый `python`; в Linux проверьте `locale`. Если Unicode всё равно недоступен, добавьте
в `config/elytrix.json` → `"ui": {"color": "none"}` — рамки и значки станут ASCII.

**Экран «поехал» после падения.**
Нажмите `Ctrl+L` (перерисовать). Если терминал остался в полноэкранном режиме —
`reset` в Linux/macOS или новое окно консоли в Windows.

**Агент отвечает, но файлы не меняет.**
Режим правок `readonly`. Проверьте строку статуса справа в шапке и переключите:
`/confirm auto` или `/confirm ask`.

**Шлюз не поддержал инструменты (400).**
Агент сам переходит на текстовый протокол: модель отвечает JSON-ом
`{"tool": "read", "args": {...}}`, а агент выполняет его как обычный вызов. Работа
продолжается, в ленте появится пометка.

**Промпт-кэш отключился сам.**
Если шлюз ответил 400 на пометки `cache_control`, ELYTRIX отключает кэш до конца сессии
и работает без него — это не ошибка, а подстройка. Видно в `/doctor` и `/status.json`.
