# Безопасность: ключ, чужой код и агент с доступом к файлам

Три вещи, которые надо понимать, прежде чем работать. Всё остальное — детали.

---

## 1. Ключ

| Правило | Почему |
|---|---|
| Хранить в переменной окружения `SMARTAPI_KEY`, не в файлах проекта | файл можно случайно закоммитить или отправить, переменную — нет |
| Не отправлять ключ в переписку и на скриншоты | `sk-smart-…` даёт полный доступ к вашему балансу |
| Засветился — отозвать и создать новый | отзыв не влияет на остаток баланса, промедление обнуляет 8 млн |
| Не прописывать ключ в файлы самого сайта | сайт может уехать в интернет вместе с ключом |

Запускатор `windows\START-SMARTAPI.bat` сохраняет ключ в переменную окружения пользователя
и больше не спрашивает. Проверить — `echo %SMARTAPI_KEY%` в новом окне терминала.

## 2. Шлюз видит ваши запросы

`api.smartapi.shop` — посредник. Через него идёт всё, что вы отправляете модели: код файлов,
тексты задач, историю диалога. Дешевле это, чем официальный Claude, именно потому, что
аккаунт чужой, и вы не можете знать, что с логами делается дальше.

**Что не пропускать через шлюз:**

* рабочий код под NDA, клиентские проекты, чужие персональные данные;
* `.env`, пароли, токены, приватные ключи, дампы баз;
* переписку и документы, которые не должны покидать ваш компьютер.

**Что делать вместо этого:**

* `/model local` в агенте — локальная Ollama, запросы не покидают компьютер;
* для секретов — вообще не давать их агенту: он читает `.env` только по прямой просьбе,
  но лучше держать такие файлы вне рабочей папки.

Подключение шлюза через роутер этого не меняет — данные всё равно идут к посреднику.
Роутер отвечает за деньги и надёжность, не за приватность.

## 3. Агент правит файлы

Что уже сделано в самом агенте (`agent/freecoder_agent.py`):

| Защита | Как работает |
|---|---|
| Ограничение папкой | все операции только внутри рабочей папки, выход наружу запрещён (есть тест) |
| Подтверждение правок | перед применением показывается diff, применяется после `y` |
| Резервные копии | каждая изменённая версия лежит в `.freecoder/` внутри проекта, `/undo` откатывает |
| Предпросмотр | `--dry-run` — показать план и ничего не трогать |
| Опасные команды заблокированы | `rm -rf /`, `format`, `curl \| sh`, `npm publish` и подобное — отказ |
| Команды отдельно | запуск команд разрешается только флагом `--allow-cmd` |

Чего агент **не** умеет и не должен: трогать файлы вне рабочей папки, менять системные
настройки, устанавливать программы. Если задача требует чего-то такого — делайте вручную.

Практические правила:

* не запускайте агента в папке, где лежит вообще всё (`C:\`), — дайте ему папку проекта;
* первую работу делайте с подтверждениями, без `/yes`;
* свежий проект — под git (`git init`), тогда `/undo` не единственный способ отката.

## 4. Чужие установщики и «настройщики»

Продавцы таких шлюзов любят предлагать «интерактивную настройку за минуту»:

```
npm install -g https://их-сайт/их-пакет.tgz
```

и запуск вроде `smart-cfg`. **Не запускайте это.** Почему:

* `preinstall` / `postinstall` в пакете исполняются с вашими правами — это обычный код,
  а не настройка;
* инструмент, который умеет прописать `ANTHROPIC_BASE_URL` и токен, умеет и **перенаправить
  весь ваш трафик** на другой шлюз или на чужой аккаунт;
* почему обычный `npm install` из npmjs.org безопаснее: у пакета есть автор, история версий
  и provenance; у пакета по прямой ссылке на .tgz — ничего этого нет.

Всё, что делает их настройщик, вы уже сделали руками — и, в отличие от него, видите, что именно
прописано (см. `docs/03-ПОДКЛЮЧЕНИЕ-ПРИЛОЖЕНИЙ.md`).

Если очень хочется проверить чужой пакет до установки — в репозитории есть разборщик:

```powershell
python tools\inspect_npm_package.py путь\к\пакету.tgz --report пакет-отчёт.json
```

Он считает SHA-256, распаковывает в песочницу, ищет автоскрипты, доступ к файлам с секретами
(`.ssh`, `.aws`, `settings.json`), сетевые отправки, автозапуск и обфускацию. Анализ статический:
код не исполняется. Ненужные автоскрипты можно отключить: `npm install --ignore-scripts`.

## 5. Чему верить нельзя, а чему можно

| Не верить | Верить |
|---|---|
| «безлимит», «пожизненно», «официальный доступ» | отчёту `tools/check_api_key.py` и остатку в кабинете |
| обещанию, что ключ «не перепродаётся» | правилу «ключ может умереть в любой момент» → держите резерв включённым |
| чужому настройщику, который «всё сделает сам» | ручной настройке из `docs/03`, где всё на виду |

Логика простая: покупая перепродажу доступа, вы приобретаете **время работы модели**,
а не собственность. Оно может закончиться не по вашей вине — поэтому в конфиге ниже SmartAPI
и стоят бесплатные модели и локальная Ollama. Когда ключ умрёт, работа не встанет.

## Если что-то всё-таки произошло

1. **Ключ утёк** → отозвать в кабинете, создать новый, заменить в запускаторе.
2. **Деньги продолжают списываться** → отозвать ключ: без ключа шлюз запросы не обслужит.
3. **Подозрение на чужой код в системе** (после запуска чужого установщика) → проверить
   автозапуск (`shell:startup`, Планировщик заданий, службы), сменить пароли к почте/аккаунтам,
   где были ключи, проверить `%USERPROFILE%\.claude\settings.json` и переменные окружения
   на подменённые адреса.
4. **Агент что-то сломал в проекте** → `/undo`, а если поздно — резервные копии в `.freecoder/`.
