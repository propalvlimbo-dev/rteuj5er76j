# Безопасность: что агент может сломать и как это исключено

Агент — это программа, которой вы даёте право менять файлы и запускать команды.
Относиться к этому надо как к стажёру: он полезен, но за ним нужен присмотр.
Вот что сделано в этом проекте, чтобы присмотр не требовал нервов.

---

## 1. Что агент умеет и чего не умеет

**Умеет:** читать файлы, искать по содержимому, создавать и править файлы, удалять файлы,
запускать команды в папке проекта, делать diff, откатывать свои правки.

**Не умеет (заблокировано кодом):**
* выходить за пределы рабочей папки — любой путь вида `../../` или `C:\Windows\...`
  отклоняется с ошибкой (есть тест `test_path_traversal_blocked`);
* выполнять разрушительные команды: `rm -rf /`, `format C:`, `diskpart`, `mkfs`,
  `shutdown`, `curl ... | sh`, `npm publish`, `git push --force` и подобное
  (тест `test_dangerous_command_blocked`).

## 2. Три уровня защиты от «испортил проект»

1. **Диффы до применения.** По умолчанию агент показывает unified diff и спрашивает
   `y/N/a`. Нажали `N` — правка не применяется, агент получит «пользователь отклонил»
   и предложит другой вариант.
2. **Резервные копии.** Перед каждой правкой файл копируется в
   `.freecoder\backups\<сессия>\`. Команда `/undo` возвращает всё назад — даже удалённые файлы.
3. **Git.** Лучший друг: если проект под git, после работы агента достаточно
   `git diff`, чтобы прочитать все изменения, и `git checkout .`, чтобы вернуть как было.
   Отдельно рекомендуется работать в ветке: `git switch -c ai-fixes`.

## 3. Режимы запуска

| Режим | Как | Когда нужен |
|---|---|---|
| С подтверждением (по умолчанию) | без флагов | первый запуск, незнакомый проект |
| Автоматический | `--yes` | когда доверяете агенту и есть git |
| Только просмотр | `--dry-run` | «покажи, что сделал бы, но не трогай» |
| Без команд | без `--allow-cmd` | если не хотите, чтобы агент что-то запускал |
| Только локальная модель | `--model local` | закрытый/коммерческий код |

## 4. Приватность: куда уходят ваши файлы

Это важно понимать: агент отправляет содержимое файлов **во внешние сервисы** —
он иначе работать не может.

| Провайдер | Что с данными |
|---|---|
| Google AI Studio (free) | на бесплатном тарифе запросы могут использоваться для улучшения продуктов (вне ЕС/Великобритании) |
| Groq | по правилам — не обучают на данных API |
| Mistral (free) | данные могут использоваться для улучшения моделей, если не отключить в настройках |
| OpenRouter | зависит от выбранной модели; смотрите политику модели |
| NVIDIA NIM | формулировка «для оценки», не для конфиденциальных данных |
| Z.ai GLM | не для коммерческого использования |
| **Ollama (локально)** | **ничего никуда не уходит** — данные не покидают ваш компьютер |

Практическое правило:
* личные проекты, пет-проекты, учебный код — любые бесплатные провайдеры;
* коммерческий код с NDA, чужие персональные данные, ключи и пароли —
  **`--model local`** или платный тариф с договором;
* `.env`, `*.key`, `id_rsa`, `.pem` агент читать не должен; в промпте заложено правило
  «не трогать секреты без прямой просьбы», но лучше просто держать их вне рабочей папки
  или добавить в `.gitignore` и не давать агенту задач про них.

## 5. Что делать перед первым запуском (5 минут, снимает 90% рисков)

```powershell
cd C:\Projects\ваш_проект
git status                  # если это ещё не git-репозиторий:
git init && git add -A && git commit -m "до экспериментов с ИИ"
git switch -c ai
```

Теперь любой каприз агента откатывается одной командой: `git checkout .`

Ещё полезно:
* держите отдельную копию проекта (или облачную синхронизацию);
* не запускайте агента в системных папках (`C:\Windows`, `C:\Program Files`) —
  он всё равно не сможет, но и не нужно;
* не давайте задачи, содержащие секреты, если работаете через облако.

## 6. Про «ротацию ключей» и правила сервисов

Роутер переключает **разные сервисы** и **разные ваши ключи** (например, личный и рабочий).
Это нормальная практика. А вот регистрировать 10 аккаунтов Google, чтобы обойти
бесплатную квоту, — нарушение правил сервиса и почти гарантированная блокировка аккаунта.
Не делайте так; вместо этого добавьте сервисы, у которых квоты независимы (их шесть),
и локальную модель.

## 7. Журнал: что агент делал

Каждая сессия записывается в `<проект>\.freecoder\sessions\<дата>-<id>.jsonl`:
задача, каждый вызов модели, каждый вызов инструмента, результат, итог.
Полезно, когда хочется понять «а что он вообще сделал».

Панель роутера <http://127.0.0.1:8788/> показывает последние 25 запросов: провайдер,
успех/ошибка, объём токенов. Никаких ваших файлов там нет — только метаданные.
