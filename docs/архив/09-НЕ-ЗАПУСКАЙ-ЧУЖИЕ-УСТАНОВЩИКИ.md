# `npm install -g https://smartapi.shop/...tgz` — почему я это запускать не буду

Разбор команды из инструкции продавца:

```
npm install -g https://smartapi.shop/smart-config-models.tgz --no-audit --no-fund
smart-cfg
```

Короткий ответ: **это не установка программы, это запуск чужого кода у себя на компьютере
с вашими правами.** И самое обидное — это совершенно не нужно: всё, что делает их мастер
настройки, вы можете сделать руками за две минуты и ничего не запускать.

---

## 1. Что реально происходит по этой команде

1. `npm` скачивает архив с чужого сайта — **не из официального реестра npm**.
   Значит: нет истории публикации, нет подписи provenance, нет проверок npm,
   нет версионирования. По той же самой ссылке завтра может лежать уже совсем другой код.
2. При установке npm **сам запускает** скрипты `preinstall`, `install`, `postinstall`
   из `package.json`. Это стандартный механизм npm, и он выполняется от вашего имени —
   до того, как вы что-либо запустите и до того, как что-либо прочитаете.
3. Только потом вы запускаете `smart-cfg`, и он правит конфиги ваших ИИ-инструментов.

Флаг `--no-audit --no-fund` в их команде просто отключает проверки и лишний вывод.

## 2. Почему «`smart-cfg` прописывает base_url и ключ» — это самое опасное место

По описанию продавца мастер сам подставляет `base_url` и ключ в Claude Code, Codex, OpenCode.
Давайте честно: **это ровно та же возможность, которая нужна вредоносному коду.**

Что можно сделать, имея право писать в `~/.claude/settings.json`, `~/.codex/config.toml`,
`~/.config/opencode/opencode.json`:

* подменить `ANTHROPIC_BASE_URL` / `baseURL` так, что **все ваши запросы и весь ваш код
  пойдут через чужой сервер** — и вы этого не заметите, внешне всё работает;
* вытащить ваши API-ключи и токены из тех же конфигов;
* дописать в профиль оболочки команду, которая будет срабатывать при каждом запуске терминала;
* повесить автозапуск (планировщик Windows, cron, LaunchAgents).

Пока пакет честный — это «удобный мастер настройки». Но вы не можете проверить,
что будет в версии, которая завтра ляжет по этой же ссылке. Разница между удобным
установщиком и вредоносом здесь — только в намерении, а намерение меняется на их стороне,
без вашего ведома и без вашего согласия.

## 3. Где выход: настройка руками, без установщика

Мастер подставляет всего несколько значений: **адрес шлюза** и **ваш ключ**.
Оба выдаются в личном кабинете продавца — их можно вписать самому. Тогда вы не запускаете
никакого чужого кода и точно видите, что и куда прописано.

### OpenCode

`%USERPROFILE%\.config\opencode\opencode.json` (Windows) или `~/.config/opencode/opencode.json`:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "smartapi": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "SmartAPI",
      "options": {
        "baseURL": "АДРЕС_ИЗ_КАБИНЕТА/v1",
        "apiKey": "sk-smart-ВАШ-КЛЮЧ"
      },
      "models": {
        "claude-opus-5": { "name": "Opus 5 (шлюз)" }
      }
    }
  },
  "model": "smartapi/claude-opus-5"
}
```

**Точный `baseURL` и ID моделей — в личном кабинете продавца** (обычно вид `https://…/v1`;
у похожих шлюзов это `api.<домен>/v1` для OpenAI-формата и `api.<домен>` для Anthropic).
Ключ выглядит как `sk-smart-…`.

### Claude Code

`~/.claude/settings.json`:

```json
{
  "env": {
    "ANTHROPIC_BASE_URL": "АДРЕС_ИЗ_КАБИНЕТА",
    "ANTHROPIC_API_KEY": "sk-smart-ВАШ-КЛЮЧ"
  },
  "model": "opus"
}
```

### Cline / Kilo Code / Continue (VS Code)

Провайдер `OpenAI Compatible`, Base URL — адрес из кабинета с `/v1` на конце,
API Key — ваш `sk-smart-…`, Model ID — ID модели из каталога.

### Наш роутер (с низким приоритетом — как дополнение)

```json
{
  "name": "smartapi",
  "kind": "openai",
  "base_url": "АДРЕС_ИЗ_КАБИНЕТА/v1",
  "keys": ["sk-smart-ВАШ-КЛЮЧ"],
  "priority": 50,
  "models": ["claude-opus-5"],
  "notes": "Сторонний шлюз: используется только когда официальные источники недоступны"
}
```

Приоритет 50 значит, что при любом сбое шлюза работа продолжится на бесплатных моделях
и локальной Ollama, а вы этого не заметите.

## 4. Если всё равно хотите проверить чужой пакет — сначала разберите его

**Никогда не запускайте npm-пакет с чужого сайта, не посмотрев, что внутри.** Для этого
в репозитории есть инструмент:

```powershell
python tools\inspect_npm_package.py https://smartapi.shop/smart-config-models.tgz --report smartapi.json
```

Он **ничего не выполняет** — только читает:

* показывает SHA-256 архива (сохраните: если при следующем скачивании хеш другой —
  значит содержимое изменилось);
* ищет скрипты, которые запустятся **при установке** (`preinstall`/`install`/`postinstall`);
* находит в коде обращения к `~/.ssh`, `~/.aws`, `.env`, cookies браузера, крипто-кошелькам;
* находит отправку данных на публичные приёмники (webhooks Discord/Telegram, pastebin), сбор
  всего окружения, обфускацию, автозапуск, правку профилей оболочки, опасные записи в архиве;
* печатает вердикт: **ЧИСТО / ОСТОРОЖНО / ПОДОЗРИТЕЛЬНО / ОПАСНО** и JSON-отчёт.

Пришлите мне этот отчёт (или сам файл) — я разберу построчно.

### Ручной способ без инструмента

```powershell
curl -o pkg.tgz https://smartapi.shop/smart-config-models.tgz
tar -tzf pkg.tgz                      # что внутри
tar -xzf pkg.tgz package/package.json # посмотреть только манифест
type package\package.json             # найти секцию scripts
```

Смотрите на `scripts` — блоки `preinstall`, `install`, `postinstall`, `prepare` запускаются
автоматически. Если там `curl … | bash`, `node setup.js`, `npm i` чего-то постороннего —
это красный флаг.

### Установка без автоскриптов

Если после разбора решились:

```powershell
npm install -g .\pkg.tgz --ignore-scripts   # код не выполнится при установке
npm ls -g --depth=0                          # что поставилось
```

Затем запускайте сам CLI и смотрите, что он делает, — но уже без «сюрпризов» на установке.

## 5. Чек-лист, если всё-таки запускаете чужой установщик

1. **Отдельная среда.** Виртуальная машина или отдельный пользователь Windows без доступа
   к вашим проектам, ключам и браузеру. Никогда — на основной рабочей машине.
2. **Секретов рядом нет.** В профиле, где запускаете, не должно быть `~/.ssh`, `~/.aws`,
   `.npmrc` с токеном, `.git-credentials`, менеджера паролей, открытых сессий браузера.
3. **Снимок «до».** Скопируйте `~/.claude`, `~/.codex`, `~/.config/opencode`, `%APPDATA%\npm`
   до запуска — потом сравните.
4. **Смотрите, что изменилось после:** новые процессы, сетевые соединения, автозапуск
   (Диспетчер задач → Автозагрузка, `schtasks /query`, `reg query HKCU\...\Run`),
   изменённые конфиги.
5. **Ключи, которые были в системе, считайте скомпрометированными** и смените.

## 6. Если уже запустили — что делать сейчас

1. **Смените API-ключи**, которые видел установщик (в первую очередь те, что лежали
   в конфигах Claude Code / Codex / opencode и в переменных окружения).
2. **Проверьте конфиги на подмену адреса:** `ANTHROPIC_BASE_URL`, `baseURL`, `OPENAI_BASE_URL` —
   там должен быть только тот сервис, которым вы пользуетесь. Любой незнакомый адрес = утечка.
3. **Проверьте автозапуск и профили:** `notepad $PROFILE`, `~/.bashrc`, `~/.zshrc`,
   Диспетчер задач → Автозагрузка, `schtasks /query`, `reg query HKCU\Software\Microsoft\Windows\CurrentVersion\Run`.
4. **Удалите пакет:** `npm uninstall -g smart-config-models`.
5. Смените пароли и **токены Git**, если они лежали в открытом виде в файлах.

---

## Что в сухом остатке

* Ставить пакет по прямой ссылке с чужого домена — это доверие без проверки: код исполняется
  сразу, а содержимое по ссылке может измениться в любую минуту.
* Для «прописать base_url и ключ» установщик не нужен: это две строки в конфиге,
  которые вы можете вписать сами и полностью контролировать.
* Их модели (`gpt-6-astra`, `claude-opus-5`, `claude-fable-5-1`) — каталог **OpenCode Zen**,
  где часть моделей доступна бесплатно по обычной регистрации: `router/providers.zen.json`.
* Если всё же тянет проверить — сначала `tools/inspect_npm_package.py`, потом решение.
  Мне пришлите отчёт: разберу и скажу прямо, что там внутри.
