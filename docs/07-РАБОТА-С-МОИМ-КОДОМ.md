# Работа со своим кодом: как вести агента

Основной режим проекта: вы запускаете одну кнопку, говорите агенту, **в какой папке** ваш
проект и **что нужно сделать**. Он читает файлы сам, сам их правит, показывает правки и умеет
откатывать.

---

## Запуск

```
двойной клик → START.bat
```

Что произойдёт:

1. если ключ ещё не сохранён — спросит ключ (один раз);
2. поднимет роутер — всё в одном окне, расход виден в строке каждого шага;
3. **спросит папку проекта** — вставьте путь к своему коду, например
   `C:\Users\admin\Desktop\ИИ` или `C:\Проекты\бот`. Папка запоминается: в следующий раз
   достаточно нажать Enter;
4. откроет диалог агента в этой папке.

Дальше вы просто пишете задачи словами. Никаких команд запуска на каждый чих.

---

## Как описать задачу, чтобы получилось сразу

**Плохо:** «почини код». **Хорошо:** «в api.py функция get_user падает, если ответ пустой —
сделай проверку и верни None».

**Плохо:** «улучши проект». **Хорошо:** «добавь логирование в main.py: пиши в logs/app.log
время, имя функции и результат».

Что помогает:

* **имя файла** — агент начнёт с него, а не будет читать всё подряд (это ещё и дешевле);
* **симптом** вместо диагноза: «падает на пустом ответе» лучше, чем «неправильная обработка»;
* **одна задача за раз**: сделали — проверили — `/diff` — следующая;
* **язык и стиль**, если важно: «пиши на Python 3.11, без зависимостей, комментарии по-русски»;
* **ограничения**: «не меняй структуру папок», «не трогай config.py».

Примеры рабочих задач:

```
в bot.py команда /help не отвечает — найди причину и исправь
разбей этот длинный файл на два модуля, импорты поправь
добавь тесты для функции parse_date (пустой ввод, кривой формат)
перепиши README под текущий код
в index.html добавь секцию с ценами: три тарифа, средний выделен
сделай так, чтобы при отсутствии интернета код не падал, а писал в лог
```

## Команды в диалоге

| Команда | Что делает |
|---|---|
| `/tree` | дерево файлов рабочей папки — понять, что агент вообще видит |
| `/diff` | что изменилось за эту сессию |
| `/undo` | откатить последнюю правку |
| `/model` | все модели шлюза — Claude, GPT, Codex — с коэффициентами, выбор номером |
| `/tokens` | из чего складывается следующий запрос и сколько это токенов |
| `/history` | что агент помнит о прошлых задачах этой сессии |
| `/clear` | забыть прошлые задачи: следующая задача с чистого листа |
| `/steps 8` | сколько шагов разрешено на задачу (по умолчанию 15) |
| `/model auto` | Sonnet 4.6 — обычная работа (расход ×2) |
| `/model smart` | Opus 4.8 для сложной задачи (×4, дороже) |
| `/model cheap` | GPT-5.6 Luna (×1,7) — простые правки и экономия |
| `/cd <папка>` | сменить рабочую папку, не выходя из агента |
| `/pwd` | какая папка рабочая сейчас |
| `/confirm on \| off` | включить или выключить подтверждения (по умолчанию выключены: правки применяются сразу) |
| `/exit` | выход |

## Как это устроено и почему безопасно

* **Песочница по папке.** Агент работает только внутри указанной папки: путь наружу запрещён
  на уровне кода (это покрыто тестом). Указали `C:\Проекты\бот` — файлы из `C:\Проекты\магазин`
  он не увидит.
* **Подтверждение правок.** Каждое изменение показывается построчно, применяется после `y`.
  Ответ `n` — и файл не тронут.
* **Резервные копии.** Старые версии файлов складываются в `<папка>\.freecoder\backups\<сессия>\`.
  Если что-то пошло не так через несколько шагов — `/undo` или копия из этой папки.
* **Опасные команды заблокированы.** `format`, `rm -rf /`, `curl | sh`, `npm publish` и подобное
  агент откажется выполнять. Запуск обычных команд — только с флагом `--allow-cmd` или после `/yes`.
* **Секреты.** `.env` и подобные файлы агент читает только по прямой просьбе. Старайтесь вообще
  не давать их агенту: держите боевые ключи вне рабочей папки.

## Порядок, при котором ничего не теряется

1. **Сделайте папку проекта git-репозиторием**, если она ещё им не является:

   ```powershell
   cd C:\путь\к\проекту
   git init
   git add -A
   git commit -m "как было до агента"
   ```

   Тогда у вас два независимых способа отката: `/undo` агента и `git diff` / `git checkout`.

2. **Первые задачи — с подтверждениями**, без `/yes`: так вы увидите, как агент себя ведёт
   на вашем коде.
3. **Смотрите на расход в строке шага** — `сегодня 45.6K/400K`. Подробно про экономию:
   `docs/08-ЭКОНОМИЯ-ТОКЕНОВ.md`.
4. **Не запускайте агента в папке, где лежит вообще всё** (`C:\` или `C:\Users\admin`):
   ему нужна конкретная папка проекта.

## Если код рабочий и секретный

Код под NDA, клиентские данные, `.env`, пароли — не отправляйте через шлюз. Варианты:

* не давать агенту эти файлы вообще (самый надёжный);
* взять официальный доступ к модели — тогда запросы идут напрямую владельцу модели,
  а не через посредника (см. `docs/05-БЕЗОПАСНОСТЬ.md`);
* для правки секретов использовать обычный редактор.

## Ошибки, которые уже разобраны

| Что видно | Причина | Что делать |
|---|---|---|
| `HTTP 502 … Все провайдеры отказали` | роутер не смог отправить запрос: чаще всего шлюз не знает такую модель | выполнить /model — там список доступных моделей; поправить `models` в конфиге |
| `HTTP 400 … model does not exist` | ID модели не совпадает с каталогом шлюза | то же самое: имя из окна роутера или со страницы «Модели» |
| `HTTP 401/403` | ключ отозван или введён неверно | создать новый ключ, запустить `START.bat` заново |
| `Не могу подключиться к 127.0.0.1:8788` | роутер не поднялся | запустить `START.bat` снова |
| `Дневной лимит расхода выбран` | выбрано `tpd` зачётных токенов за сутки | подождать до полуночи по UTC или поднять `tpd` в конфиге |
| `Ключ SMARTAPI_KEY не задан` | переменная окружения пустая | запустить `START.bat` заново |
